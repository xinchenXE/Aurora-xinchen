# 数据库

数据库使用 MySQL 8（字符集 `utf8mb4`，排序规则 `utf8mb4_0900_ai_ci`），库名 `aurora`。

## 一、初始化脚本

[`sql/aurora-init.sql`](sql/aurora-init.sql) 是**完整初始化脚本**（25 张表 + 基础种子数据），新环境只需执行它：

```bash
# 在仓库根目录执行（口令即 setup/.env 中的 MYSQL_ROOT_PASSWORD）
docker exec -i aurora-mysql mysql -uroot -p'<数据库口令>' < setup/sql/aurora-init.sql
```

脚本会自行创建并使用 `aurora` 库。

脚本结构：先 `CREATE TABLE` 再 `INSERT`，已包含以下内容：

- 角色与账号：`admin` / `user` / `test` 三个角色，初始管理员 `admin@163.com` / `123456`
- 菜单、资源与角色授权（`t_menu` / `t_resource` / `t_role_resource`，含 AI 对话与照片上传接口的受保护登记）
- 站点配置（`t_website_config`）、关于页（`t_about`）、AI 人设（`t_ai_persona`）
- 定时任务（`t_job`）：访问统计、访客清理、SEO、任务日志清理等

> ⚠️ 脚本含 `DROP TABLE IF EXISTS`，**只用于全新环境初始化**，不要对已有数据的库执行。
> 可用 `grep "CREATE TABLE \`" setup/sql/aurora-init.sql | wc -l` 核实表数量（应为 25）。

## 三、资源鉴权表（改代码时必看）

后端 `ResourceRoleAuthorizationManager` 的语义是：**路由在 `t_resource` 中登记且 `is_anonymous=0` 才进入角色校验；
未登记的路由直接放行**。因此新增受保护接口时，必须同步：

1. 在 `t_resource` 登记 URL + 请求方法（`is_anonymous=0`），在 `t_role_resource` 给对应角色授权；
2. 在 `aurora-init.sql` 中补充同样的数据（保持初始化脚本与线上库一致）；
3. 重启后端（资源表在启动时加载）。

仓库中已有两个幂等示例脚本，可照此新增：

| 脚本 | 作用 |
| --- | --- |
| [`sql/03-ai-chat-resource-auth.sql`](sql/03-ai-chat-resource-auth.sql) | 把 `/ai/chat`、`/ai/chat/stream` 登记为需登录资源 |
| [`sql/04-photo-upload-resource-auth.sql`](sql/04-photo-upload-resource-auth.sql) | 补登记照片/相册封面上传接口，堵住匿名上传 |

## 四、旧版升级包（从旧版 Aurora 升级）

如果库是**旧版 aurora 初始化脚本**建的（24 张表、无 `t_ai_persona`），执行
[`sql/upgrade-from-old/`](sql/upgrade-from-old/) 下的增量包，顺序见其 README：

| 顺序 | 文件 | 作用 |
| --- | --- | --- |
| 1 | `01-add-ai-persona-table.sql` | 新建 `t_ai_persona`（旧版没有） |
| 2 | `01b-add-ai-persona-menu.sql` | 补后台「AI人设设置」菜单与资源登记 |
| 3 | `02-ai-persona-extend.sql` | 补 `role_name` / `greeting` 列 |
| 4 | `03-ai-chat-resource-auth.sql` | AI 对话接口资源登记与授权 |
| 5 | `04-photo-upload-resource-auth.sql` | 照片上传接口资源登记 |
| 6 | `05-log-retention-cleanup.sql` | 90 天日志清理任务（已修正 `job_group='默认'`） |
| 7 | `06/07-content-seed-*.sql` | **可选**，仅本地开发虚构内容 |

`00-upgrade-all.sql` 是 1~6 的内联合并版（自带 `USE aurora`，可直接管道执行）。执行后**必须重启后端**。

> 旧库的 `t_article.article_abstract` 列新版代码不再读写，**保留不删**（删列会丢历史摘要）。

## 五、迁移与开发脚本（全新库可选）

初始化脚本已是最新结构；以下脚本用于补齐或本地开发，均为幂等写法。

| 文件 | 用途 | 何时需要 |
| --- | --- | --- |
| `sql/02-ai-persona-extend.sql` | 给 `t_ai_persona` 增加 `role_name`、`greeting` 列 | 初始化脚本已含新列；仅旧库升级时需要 |
| `sql/03-ai-chat-resource-auth.sql` | AI 对话接口资源登记与角色授权 | 旧库补齐时 |
| `sql/04-photo-upload-resource-auth.sql` | 照片上传接口资源登记 | 旧库补齐时 |
| `sql/05-log-retention-cleanup.sql` | 登记每日清理 90 天前操作/异常日志的定时任务 | 初始化脚本未含该任务；新环境也可执行一次 |
| `sql/06-content-seed-local.sql` | 写入**虚构**的演示内容（分类/标签/文章/说说/相册），ID 从 90001 起 | 仅本地开发想看到有内容的首页时 |
| `sql/07-content-seed-cleanup.sql` | 删除上述演示内容（只删 `id >= 90001`） | 演示结束后清理 |

`05-log-retention-cleanup.sql` 会向 `t_job` 登记任务（每日 03:00 执行 `auroraQuartz.clearExpiredLogs`），
未执行时后端不会有日志清理任务。

## 六、备份与恢复

```bash
# 导出（备份）
docker exec aurora-mysql sh -c \
  'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --routines --triggers \
   --default-character-set=utf8mb4 --add-drop-table aurora > /tmp/aurora-dump.sql'
docker cp aurora-mysql:/tmp/aurora-dump.sql ./aurora-dump-$(date +%Y%m%d).sql

# 恢复
docker cp ./aurora-dump-YYYYMMDD.sql aurora-mysql:/tmp/aurora-dump.sql
docker exec aurora-mysql sh -c \
  'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 aurora < /tmp/aurora-dump.sql'
```

Windows PowerShell 中 `$(date ...)` 不可用，替换为固定文件名即可；`$MYSQL_ROOT_PASSWORD` 也可直接写实际口令
（注意不要提交含真实口令的命令记录）。

备份文件不要放进 `setup/sql/`，也不要覆盖 `sql/aurora-init.sql`。

## 七、Maxwell 与搜索

- 使用 Elasticsearch 搜索（`search.mode: elasticsearch`）时，Maxwell 从 MySQL binlog 把 `t_article` 的
  标题、内容、状态、删除标记同步到 RabbitMQ，再由后端的 `MaxWellConsumer` 写入 ES；
  因此 MySQL 需要开启 `binlog-format=ROW`（`docker-compose.yml` 已配置）。
- 不需要 ES 时，在 Nacos 配置中改为 `search.mode: mysql`，同时可以不启动 `aurora-es` 与 `aurora-maxwell` 容器。

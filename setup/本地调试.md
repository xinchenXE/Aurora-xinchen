# 本地调试

> 适用：Windows / macOS / Linux 本地开发环境。
> 命令以 PowerShell 为主，bash 下把 `$env:X=...` 换成 `export X=...` 即可。

## 一、启动中间件

推荐使用 [`docker-compose.yml`](docker-compose.yml)：

```bash
cd setup
cp .env.example .env      # 编辑 .env，替换所有 CHANGEME
docker compose up -d
docker compose ps         # 7 个容器全部 Up
```

确认端口就绪（容器 `restart=always`，机器重启后需等 30~60 秒）：

```powershell
foreach ($p in @(3306,6379,5672,8300,9200,9000)) {
  "{0}: {1}" -f $p, (Test-NetConnection 127.0.0.1 -Port $p -WarningAction SilentlyContinue).TcpTestSucceeded
}
```

**启动顺序**：必须先确认容器全部就绪，再启动后端。后端启动时 Druid 连接池会立即连 MySQL，
容器没起会直接报 `Connection refused`。

| 容器 | 镜像 | 端口 | 说明 |
| --- | --- | --- | --- |
| aurora-mysql | mysql:8.4 | 3306 | 首次启动自动导入 `sql/aurora-init.sql` |
| aurora-redis | redis:7.4 | 6379 | 应用固定使用 DB 1 |
| aurora-rabbitmq | rabbitmq:3.13-management | 5672 / 15672 | 管理台 15672 |
| aurora-nacos | nacos/nacos-server:v3.2.3 | 8300→8848 / 9300→9848 / 控制台 8880 | 端口平移原因见下 |
| aurora-es | elasticsearch:7.17.27 | 9200 | `search.mode=mysql` 时可不启动 |
| aurora-maxwell | zendesk/maxwell:latest | — | 日志：`docker logs aurora-maxwell` |
| aurora-minio | minio/minio:latest | 9000 / 9001 | 控制台 9001 |

> **Nacos 端口平移**：HTTP 映射为宿主 `8300`、gRPC 映射为 `9300`、控制台映射为 `8880`
> （容器内仍是 8848/9848/8080）。ES 的 9300 传输端口被 Nacos gRPC 占用后，ES 改为 `9301:9300`；
> 后端走 ES 的 HTTP REST（9200），无需改代码。

不用 compose 时，可逐个 `docker run`（口令换成你自己的）：

```bash
docker run -d --name aurora-mysql --restart=always -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD='<口令>' mysql:8.4

docker run -d --name aurora-redis --restart=always -p 6379:6379 \
  redis:7.4 --requirepass '<口令>'

docker run -d --name aurora-rabbitmq --restart=always -p 5672:5672 -p 15672:15672 \
  -e RABBITMQ_DEFAULT_USER=aurora -e RABBITMQ_DEFAULT_PASS='<口令>' rabbitmq:3.13-management

docker run -d --name aurora-es --restart=always -p 9200:9200 \
  -e discovery.type=single-node -e ES_JAVA_OPTS='-Xms256m -Xmx256m' --memory=640m -p 9301:9300 elasticsearch:7.17.27

# IK 分词器（GitHub 不通时用国内镜像源，版本必须与 ES 一致）
docker exec -it aurora-es bin/elasticsearch-plugin install --batch \
  https://release.infinilabs.com/analysis-ik/stable/elasticsearch-analysis-ik-7.17.27.zip
docker restart aurora-es

docker run -d --name aurora-minio --restart=always -p 9000:9000 -p 9001:9001 \
  -e MINIO_ROOT_USER=aurora -e MINIO_ROOT_PASSWORD='<口令>' \
  minio/minio server /data --console-address ':9001'

docker run -d --name aurora-nacos --restart=always -p 8300:8848 -p 9300:9848 -p 8880:8080 \
  -e MODE=standalone -e NACOS_AUTH_ENABLE=true \
  -e NACOS_AUTH_TOKEN='<base64,解码后至少32字节>' \
  -e NACOS_AUTH_IDENTITY_KEY='<key>' -e NACOS_AUTH_IDENTITY_VALUE='<value>' \
  -e JVM_XMS=256m -e JVM_XMX=512m -e JVM_XMN=128m --memory=768m \
  nacos/nacos-server:v3.2.3
```

Maxwell 需要数据库开启 `binlog-format=ROW`，推荐直接用 compose；手动启动时把 `aurora.maxwell`
的完整参数照抄 `docker-compose.yml` 中的 `maxwell.command` 即可。

## 三、后端打包与启动

以下命令在**仓库根目录**执行：

```bash
cd aurora-xinchen
java -version                            # 预期 25.x
mvn -B -ntp clean package -DskipTests    # 产物 target/aurora-xinchen-0.0.1.jar
mvn -B -ntp test                         # 单元测试
```

启动前复制引导配置并填入命名空间与地址（仓库根目录）：

```bash
cp setup/bootstrap.properties.template aurora-xinchen/src/main/resources/bootstrap.properties
```

```powershell
$env:NACOS_PASSWORD = '<你的Nacos口令>'   # 仅当前终端会话有效
cd aurora-xinchen
java -jar target/aurora-xinchen-0.0.1.jar
```

启动成功标志：日志出现 `Started AuroraXinchenApplication`，`8080` 端口可访问。
接口文档（knife4j）：<http://localhost:8080/doc.html>。

## 四、接口冒烟

```powershell
# 1. 网站配置（前台首屏接口）
Invoke-RestMethod 'http://localhost:8080/'

# 2. 文章列表
Invoke-RestMethod 'http://localhost:8080/articles/all?current=1&size=5'

# 3. 分类列表
Invoke-RestMethod 'http://localhost:8080/categories/all'

# 4. 登录拿 token（初始化脚本内置管理员）
$login = Invoke-RestMethod -Uri 'http://localhost:8080/users/login' -Method Post `
  -Body 'username=admin@163.com&password=123456' -ContentType 'application/x-www-form-urlencoded'
$token = $login.data.token

# 5. 带鉴权的管理接口（预期 flag=True code=20000）
Invoke-RestMethod 'http://localhost:8080/admin/articles?current=1&size=5' `
  -Headers @{ Authorization = "Bearer $token" }

# 6. ES 搜索（search.mode=elasticsearch 时）
Invoke-RestMethod 'http://localhost:8080/articles/search?keywords=关键词'

# 7. AI 对话（需登录；Nacos 中配置真实 API Key 后才有实际回复）
Invoke-RestMethod 'http://localhost:8080/ai/chat' -Method Post `
  -Headers @{ Authorization = "Bearer $token" } `
  -Body '{"message":"你好"}' -ContentType 'application/json;charset=utf-8'
# 反例（预期）：不带 Authorization 头 → {"flag":false,"code":40001,"message":"用户未登录"}
```

> 初始管理员口令为公开的演示值，首次登录后请立即修改。

## 五、Maxwell → ES 链路测试

```powershell
# 1. 插入测试文章
docker exec -e MYSQL_PWD='<口令>' aurora-mysql mysql -uroot --default-character-set=utf8mb4 -e "INSERT INTO aurora.t_article (user_id, article_title, article_content, is_top, is_featured, is_delete, status, type, create_time) VALUES (1, '链路测试文章', 'Maxwell to Elasticsearch pipeline test', 0, 0, 0, 1, 1, NOW())"

# 2. 等 10 秒同步后查 ES 文档数（预期增加）
Start-Sleep 10
curl.exe -s 'http://localhost:9200/article/_count'

# 3. 走应用搜索接口（关键词用完整小写词，避免分词不匹配）
Invoke-RestMethod 'http://localhost:8080/articles/search?keywords=maxwell'

# 4. 清理：逻辑删除 -> ES 标记 isDelete；再物理删除 -> ES 文档删除
docker exec -e MYSQL_PWD='<口令>' aurora-mysql mysql -uroot -e "UPDATE aurora.t_article SET is_delete=1 WHERE article_title='链路测试文章'"
Start-Sleep 10
docker exec -e MYSQL_PWD='<口令>' aurora-mysql mysql -uroot -e "DELETE FROM aurora.t_article WHERE article_title='链路测试文章'"
```

## 六、前端

以下命令在**仓库根目录**执行：

```powershell
cd aurora-blog
npm ci
npm run serve -- --port 8081     # http://localhost:8081
```

```powershell
cd aurora-admin
npm ci
npm run serve -- --port 8082     # http://localhost:8082
```

两份 `vue.config.js` 均未设置端口（默认 8080 与后端冲突），dev 时**必须**用 `-- --port` 指定。
`/api` 会代理到 `http://localhost:8080`（`pathRewrite: ^/api -> ''`）。

## 七、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动报 `Communications link failure` / `Connection refused` | MySQL 容器没起或没就绪 | `docker ps` 确认，等待 30 秒再启动后端 |
| 启动报 `Profile '乱码' must contain a letter...` | 工作目录下存在 `bootstrap.properties` 模板被误读 | 模板只放 `setup/`，不要在仓库根放名为 `bootstrap.properties` 的文件 |
| 启动报 Nacos 连接失败 / 权限错误 | 未注入 `NACOS_PASSWORD`，或 Nacos 鉴权配置不匹配 | 注入环境变量并核对 Nacos 账号 |
| `OpenAI API key must be set` | Nacos 中 `spring.ai.openai.api-key` 仍是占位符 | 填入真实 Key，或不调用 `/ai/chat` |
| Nacos 配置改了但应用没生效 | 配置缓存 | 重启应用（`refresh-enabled` 仅对可刷新的 Bean 生效） |
| 前端 `npm` 命令找不到 | Node 不在 PATH | 把 Node 安装目录加入 PATH |
| 搜索 0 命中但 ES 有文档 | 分词不匹配（驼峰长词是单个 token） | 用完整小写词搜索 |
| ES 容器 Up 但 9200 连接被拒 | Windows Hyper-V/WinNAT 动态端口保留了 9200（休眠唤醒后常见） | 管理员执行 `net stop winnat` → `netsh int ipv4 add excludedportrange protocol=tcp startport=9200 numberofports=1 store=persistent` → `net start winnat`，再重建 ES 容器 |
| Nacos 反复重启，日志 `the length of secret key must great than or equal 32 bytes` | `NACOS_AUTH_TOKEN` 解码后不足 32 字节 | `openssl rand -base64 32` 重新生成，写入 `.env` 后 `docker compose up -d --force-recreate nacos` |
| Redis 容器反复重启，日志报 `Can't initialize Background Jobs` | 宿主环境与 Redis 最新版不兼容 | 改用 `redis:7.4` 或 `redis:7.0.10` 镜像 |
| 前端 dev 端口冲突 | 端口被占用或与后端相同 | 换一个 `-- --port` |

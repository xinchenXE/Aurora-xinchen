# 镜像拉取与整理

本文件汇总部署需要用到的**全部镜像**与拉取/整理命令。版本与 [`docker-compose.yml`](docker-compose.yml) 保持一致；
国内网络拉取失败时见文末「镜像加速」。

## 一、镜像清单

| 用途 | 镜像 | 版本 | 体积（约） | 备注 |
| --- | --- | --- | --- | --- |
| 数据库 | `mysql` | `8.4` | 600MB | 需 `binlog-format=ROW` 供 Maxwell |
| 缓存 | `redis` | `7.4` | 130MB | 应用使用 DB 1 |
| 消息队列 | `rabbitmq` | `3.13-management` | 220MB | 带管理台 |
| 配置中心 | `nacos/nacos-server` | `v3.2.3` | 500MB | 单独暴露 8300/9300/8880 |
| 搜索 | `elasticsearch` | `7.17.27` | 650MB | 轻量方案可不装 |
| CDC | `zendesk/maxwell` | `latest` | 400MB | MySQL → RabbitMQ → ES |
| 对象存储 | `minio/minio` | `latest` | 180MB | OSS 可替代 |
| 前端静态服务 | `nginx` | `alpine` | 50MB | 方式二使用 |
| 后端运行时 | `eclipse-temurin` | `25-jre` | 350MB | 构建后端镜像的基础镜像 |

> Nacos 3.x 必须使用 `v3.x` 标签（2.2.0 的表结构不兼容，见文末「Nacos 版本说明」）。

## 二、一次性拉取全部镜像

在仓库根目录执行：

```bash
docker pull mysql:8.4
docker pull redis:7.4
docker pull rabbitmq:3.13-management
docker pull nacos/nacos-server:v3.2.3
docker pull elasticsearch:7.17.27
docker pull zendesk/maxwell:latest
docker pull minio/minio:latest
docker pull nginx:alpine
docker pull eclipse-temurin:25-jre
```

或者用 compose 一次拉齐（只拉镜像，不启动）：

```bash
cd setup
cp .env.example .env
docker compose pull
```

只拉需要的（轻量方案：不装 ES / Maxwell）：

```bash
for img in mysql:8.4 redis:7.4 rabbitmq:3.13-management nacos/nacos-server:v3.2.3 minio/minio:latest; do
  docker pull "$img"
done
```

## 三、核对与整理

```bash
# 核对版本与体积
docker images --format 'table {{.Repository}}\t{{.Tag}}\t{{.Size}}' \
  | grep -E 'mysql|redis|rabbitmq|nacos|elasticsearch|maxwell|minio|nginx|temurin'

# 清理悬空镜像（构建残留的 <none> 层）
docker image prune -f

# 清理全部未使用镜像（谨慎：会删掉未被容器引用的镜像）
docker image prune -a -f
```

> 建议**不要**用 `docker system prune -a`，它会连网络、构建缓存一起清空；本仓库的禁止清单也把
> `docker system prune` 列为硬停。

## 四、保存与离线搬迁（服务器无法联网时）

```bash
# A 机（有网）：按需导出
mkdir -p /opt/aurora-images
docker save -o /opt/aurora-images/aurora-images.tar \
  mysql:8.4 redis:7.4 rabbitmq:3.13-management nacos/nacos-server:v3.2.3 \
  elasticsearch:7.17.27 zendesk/maxwell:latest minio/minio:latest

# 压缩（可选，体积通常减半）
gzip -9 /opt/aurora-images/aurora-images.tar

# 传到 B 机
scp /opt/aurora-images/aurora-images.tar.gz root@<服务器IP>:/opt/

# B 机（无网）：导入
gunzip -c /opt/aurora-images.tar.gz | docker load
docker images
```

> 单镜像导出更省事：`docker save mysql:8.4 | gzip > mysql-8.4.tar.gz`。

## 五、镜像加速（国内网络，2026-11-09 实测）

> 实测环境：国内网络、Docker Hub 直连 `registry-1.docker.io` **超时**，必须走镜像加速。

### 5.1 推荐加速源（按实测可用性排序）

| 加速源 | 实测结果 | 结论 |
| --- | --- | --- |
| `https://docker.1ms.run` | mysql / redis / rabbitmq / elasticsearch / nginx / temurin / **nacos** / maxwell 全部有标签 | ✅ **首选**（nacos 可用） |
| `https://docker.1panel.live` | 同上，nacos 也有 `v3.x` 标签 | ✅ 备选 |
| `https://hub.rat.dev` | 同上，返回 302 跳转，可用 | ✅ 备选 |
| `https://docker.m.daocloud.io` | 能连但标签查询返回空 / 拒绝（`DENIED`） | ⚠️ 只作兜底 |
| `docker.nju.edu.cn`、`dockerhub.azk8s.cn` | 403 | ❌ 不可用 |
| `docker.amingg.com`、`docker.1panel.top` | 429 限流 | ❌ 不可用 |
| `docker.kejilion.pro`、`dockerproxy.com`、`dockerpull.org` 等 | 不可达 / 证书错误 | ❌ 不可用 |

### 5.2 关于 nacos

用户反馈「nacos 不能用那个加速源」，实测确认：

- `docker.1ms.run` 的 `nacos/nacos-server` **包含 `v3.2.3`**（共 125 个标签，v3 系列从 `v3.0.0` 起）
- `docker.1panel.live` 同样包含 `v3.2.3`
- 之前失败的源（daocloud / nju / azk8s）确实对 nacos 返回 403/空

所以 nacos 请用 **`docker.1ms.run`** 或 **`docker.1panel.live`**。

### 5.3 两种用法

**方式一：配 daemon.json（对 Docker Hub 镜像全局生效）**

```json
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.1panel.live",
    "https://hub.rat.dev"
  ]
}
```

```bash
# Linux
systemctl daemon-reload && systemctl restart docker
# Docker Desktop：Settings → Docker Engine 粘贴后 Apply & Restart
docker info | grep -A4 "Registry Mirrors"
```

**方式二：临时带前缀拉取（不重启 Docker，最稳）**

```bash
docker pull docker.1ms.run/library/mysql:8.4
docker tag  docker.1ms.run/library/mysql:8.4 mysql:8.4

docker pull docker.1ms.run/nacos/nacos-server:v3.2.3
docker tag  docker.1ms.run/nacos/nacos-server:v3.2.3 nacos/nacos-server:v3.2.3

# 其余同理：library/redis:7.4、library/rabbitmq:3.13-management、
# library/elasticsearch:7.17.27、library/nginx:alpine、library/eclipse-temurin:25-jre、
# zendesk/maxwell:latest（注意 maxwell 不是 library/ 前缀）
```

> 打完 tag 后 compose 里的 `image:` 名称不用改。
> `registry-mirrors` 只对**未带域名的 Docker Hub 镜像**生效；`docker.elastic.co` 等第三方仓库不走它。

### 5.4 例外：MinIO

**`minio/minio` 在所有测试过的加速源上都拉不到**（`NAME_UNKNOWN` 上游回源失败 / 403），这是 MinIO 官方撤下镜像后的普遍情况。可选方案：

| 方案 | 做法 | 说明 |
| --- | --- | --- |
| A. 换兼容镜像 | `docker pull docker.1panel.live/bitnamilegacy/minio:<tag>` | Bitnami 历史归档镜像，S3 兼容，API 与 MinIO 不完全一致，需人工核对 |
| B. 用对象存储替代 | 后台「文件上传」改为 OSS | Nacos 里 `upload.mode: oss` + 填 OSS 配置即可，不依赖 MinIO 容器 |
| C. 手工导入镜像 | 在有网机器 `docker save/load` | 见第四节 |
| D. 换 RustFS 等 S3 兼容服务 | `rustfs/rustfs`（标签可查，manifest 经镜像加速可能仍 401） | 需自行验证兼容性 |

> 当前默认 `docker-compose.yml` 仍写 `minio/minio:latest`；如果拉不到，建议先走 **B（OSS）**，或临时把 compose 里的 minio 服务注释掉。

### 5.5 加速源失效时

- 加速源与限流状态会变化，优先重试或换表里下一个；
- 报 `toomanyrequests` 是上游限流，等几分钟或换源；
- 全部失败时用第四节「离线搬迁」。
## 六、版本固化建议

- 生产环境**不要用 `latest`**（本仓库的 `zendesk/maxwell`、`minio/minio` 目前是 `latest`）。
  首次拉取成功后记下实际版本，把 compose 改成具体标签：

```bash
docker inspect --format '{{.Config.Image}} {{index .RepoDigests 0}}' aurora-minio aurora-maxwell
```

- 升级镜像前先备份数据库（[`数据库.md`](数据库.md) 第六节）。

## 七、Nacos 版本说明

| 项 | 说明 |
| --- | --- |
| 2.2.0 → 3.2.3 | **表结构不兼容**：3.x 新增 `ai_resource`、`ai_resource_version`、`config_info_gray`、`pipeline_execution`，`his_config_info` 多 3 列；旧表的 `config_info_aggr` / `config_info_beta` / `config_info_tag` 3.x 不再使用 |
| 可以沿用 | 同一个 MySQL 实例、同一套账号 |
| 不可以沿用 | 旧 `nacos` 库的表结构（需补表补列或迁到新库） |
| 配置项变化 | 3.x 用 `spring.sql.init.platform=mysql`、`db.url.0`、`db.user`；鉴权用 `nacos.core.auth.plugin.nacos.token.secret.key`、`nacos.core.auth.server.identity.key/value` |

## 八、IK 分词器（ES 插件，不是镜像）

Elasticsearch 版本与项目一致时用 `7.17.27`。GitHub 不可达时用国内镜像：

```bash
# 推荐：容器内直接装（INFINI Labs 官方国内源）
docker exec -it aurora-es bin/elasticsearch-plugin install --batch \
  https://release.infinilabs.com/analysis-ik/stable/elasticsearch-analysis-ik-7.17.27.zip
docker restart aurora-es
```

| 下载源 | 地址 | 实测 |
| --- | --- | --- |
| INFINI Labs stable | `https://release.infinilabs.com/analysis-ik/stable/elasticsearch-analysis-ik-7.17.27.zip` | 200，4.5MB |
| INFINI get | `https://get.infini.cloud/elasticsearch/analysis-ik/7.17.27` | 200，同一 MD5 |
| GitHub 原始 | `https://github.com/medcl/elasticsearch-analysis-ik/releases/download/v7.17.27/...` | 国内服务器常超时 |

- MD5：`e46258757569459979b193d11cb3a914`
- 包内 `plugin-descriptor.properties` 的 `elasticsearch.version` 必须与 ES 版本完全一致，否则启动报版本不匹配。
- 容器内无外网时：宿主机 `unzip` 到 `.../plugins/ik/` 后重启容器。

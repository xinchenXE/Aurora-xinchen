# 服务器部署

本文说明如何在 Linux 服务器上从零部署后端、前台与后台。本地调试见 [`本地调试.md`](本地调试.md)，
数据库见 [`数据库.md`](数据库.md)。

## 一、服务器要求

| 方案 | 配置 | 说明 |
| --- | --- | --- |
| 完整版 | 2 核 4G 起 | 使用 Elasticsearch 搜索策略 |
| 轻量版 | 2 核 2G 起 | 搜索策略改为 `mysql`，不启动 ES 与 Maxwell |

带宽：使用 OSS 时对小带宽友好；使用 MinIO 自建存储建议带宽大一些，或配合 CDN。
上述配置不含 MinIO 的额外内存占用。

默认端口：后端 `8080`，Nacos `8300/9300/8880`，ES `9200`（传输端口宿主 `9301`），MySQL `3306`，Redis `6379`，RabbitMQ `5672/15672`，
ES `9200`，MinIO `9000/9001`。请只对外开放必要的端口（通常只开 nginx 的 80/443）。

## 二、安装 Docker

以下命令基于 CentOS / RHEL 系：

```bash
yum install -y yum-utils
yum-config-manager --add-repo https://mirrors.aliyun.com/docker-ce/linux/centos/docker-ce.repo
yum makecache fast
yum install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
systemctl start docker
systemctl enable docker
docker version
```

## 三、中间件

### 方式一：使用仓库编排（推荐）

把仓库或 `setup/` 目录上传到服务器后：

```bash
cd setup
cp .env.example .env      # 替换所有 CHANGEME
docker compose pull       # 先拉镜像（也可跳过，up 时自动拉）
docker compose up -d
docker compose ps
```

镜像清单、一次性拉取、离线搬迁（`docker save` / `docker load`）与国内加速源见
[`镜像拉取与整理.md`](镜像拉取与整理.md)。

MySQL 首次启动会自动导入 `sql/aurora-init.sql`。部署到公网前务必替换 `.env` 与
[`nacos-template.yml`](nacos-template.yml) 中的全部示例口令。

### 方式二：手动启动

```bash
# MySQL 8.4（开启 ROW binlog 供 Maxwell 使用）
docker run -d --name aurora-mysql --restart=always -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD='<口令>' \
  -v /usr/local/aurora/mysql/data:/var/lib/mysql \
  -v /usr/local/aurora/mysql/conf:/etc/mysql/conf.d \
  mysql:8.4 --binlog-format=ROW --server-id=1

# Redis 7.4（应用使用 DB 1）
docker run -d --name aurora-redis --restart=always -p 6379:6379 \
  -v /usr/local/aurora/redis/data:/data \
  redis:7.4 --requirepass '<口令>' --appendonly yes

# RabbitMQ
docker run -d --name aurora-rabbitmq --restart=always -p 5672:5672 -p 15672:15672 \
  -e RABBITMQ_DEFAULT_USER=aurora -e RABBITMQ_DEFAULT_PASS='<口令>' \
  -v /usr/local/aurora/rabbitmq:/var/lib/rabbitmq \
  rabbitmq:3.13-management

# MinIO
docker run -d --name aurora-minio --restart=always -p 9000:9000 -p 9001:9001 \
  -e MINIO_ROOT_USER='<账号>' -e MINIO_ROOT_PASSWORD='<口令>' \
  -v /usr/local/aurora/minio/data:/data \
  minio/minio server /data --console-address ':9001'
```

#### Elasticsearch 与 IK 分词器

```bash
mkdir -p /usr/local/aurora/elasticsearch/{data,config,plugins}
chmod -R 777 /usr/local/aurora/elasticsearch

# 注意：9300 已被 Nacos gRPC 占用（server-addr 8300 + 1000），ES 传输端口在宿主机改用 9301
docker run -d --name aurora-es --restart=always \
  -p 9200:9200 -p 9301:9300 \
  -e discovery.type=single-node \
  -e ES_JAVA_OPTS='-Xms256m -Xmx256m' \
  --memory=640m \
  -e xpack.security.enabled=false \
  -v /usr/local/aurora/elasticsearch/data:/usr/share/elasticsearch/data \
  -v /usr/local/aurora/elasticsearch/plugins:/usr/share/elasticsearch/plugins \
  elasticsearch:7.17.27

# 安装与 ES 版本一致的 IK 分词器
# ⚠️ 服务器无法访问 GitHub 时，改用下面的「国内镜像」两条命令之一。
# 方案 A（推荐）：容器内直接安装（INFINI Labs 官方国内镜像，实测可达）
docker exec -it aurora-es bin/elasticsearch-plugin install \
  --batch \
  https://release.infinilabs.com/analysis-ik/stable/elasticsearch-analysis-ik-7.17.27.zip

# 方案 B：宿主机先下载再放到插件目录（适合容器内无外网、只有宿主机能出网）
mkdir -p /usr/local/aurora/elasticsearch/plugins/ik
curl -L -o /tmp/ik.zip \
  https://release.infinilabs.com/analysis-ik/stable/elasticsearch-analysis-ik-7.17.27.zip
unzip -o /tmp/ik.zip -d /usr/local/aurora/elasticsearch/plugins/ik
chmod -R 777 /usr/local/aurora/elasticsearch/plugins/ik

docker restart aurora-es
```

> 备选下载源（与上面是同一个包，MD5 `e46258757569459979b193d11cb3a914`，4.5MB）：
>
> - `https://get.infini.cloud/elasticsearch/analysis-ik/7.17.27`
> - `https://release.infinilabs.com/analysis-ik/stable/elasticsearch-analysis-ik-7.17.27.zip`
>
> 校验方式：`md5sum ik.zip` 应等于上面的值；包内 `plugin-descriptor.properties` 的
> `elasticsearch.version` 必须是 `7.17.27`（版本不一致 ES 会拒绝加载）。
>
> 如果以后升级 ES，把 URL 里的 `7.17.27` 换成新版本号即可。

验证分词：

```bash
# 方式一：把中文写进文件再发（最稳，绕开终端编码）
cat > /tmp/analyze.json <<'JSON'
{"tokenizer":"ik_smart","text":"我爱技术"}
JSON
curl -s -XPOST 'http://localhost:9200/_analyze' \
  -H 'Content-Type: application/json' --data-binary @/tmp/analyze.json

# 方式二：用 JSON 的 \u 转义（纯 ASCII，终端编码再乱也不会出错）
# 我爱技术 = \u6211\u7231\u6280\u672f
curl -s -XPOST 'http://localhost:9200/_analyze' \
  -H 'Content-Type: application/json' \
  -d '{"tokenizer":"ik_smart","text":"\u6211\u7231\u6280\u672f"}'

# 方式三：只验证分词器已装好（不用发中文）
curl -s 'http://localhost:9200/_cat/plugins?v'
# 预期看到一行：aurora-es analysis-ik 7.17.27
```

> ⚠️ `Invalid UTF-8 middle byte 0xd2` **不是分词器问题**：是当前终端把中文按 GBK/GB2312 发给 ES。
> 换用上面任一方式即可；也可以先执行 `export LANG=C.UTF-8`（Windows 用 Git Bash 或 PowerShell 7 发请求）。

#### Maxwell（MySQL → RabbitMQ → ES）

```bash
docker run -d --name aurora-maxwell --restart=always zendesk/maxwell \
  bin/maxwell \
  --user=root --password='<数据库口令>' --host='<MySQL 地址>' \
  --producer=rabbitmq \
  --rabbitmq_user=aurora --rabbitmq_pass='<MQ 口令>' \
  --rabbitmq_host='<RabbitMQ 地址>' --rabbitmq_port=5672 \
  --rabbitmq_exchange=maxwell_exchange \
  --rabbitmq_exchange_type=fanout \
  --rabbitmq_exchange_durable=true \
  --filter='exclude: *.*, include: aurora.t_article.article_title = *, include: aurora.t_article.article_content = *, include: aurora.t_article.is_delete = *, include: aurora.t_article.status = *'
```

（`--filter` 中 `aurora` 为库名。）

#### Nacos 3

```bash
docker run -d --name aurora-nacos --restart=always \
  -p 8300:8848 -p 9300:9848 -p 8880:8080 \
  -e MODE=standalone \
  -e NACOS_AUTH_ENABLE=true \
  -e NACOS_AUTH_TOKEN='<base64，解码后至少 32 字节>' \
  -e NACOS_AUTH_IDENTITY_KEY='<key>' \
  -e NACOS_AUTH_IDENTITY_VALUE='<value>' \
  -v /usr/local/aurora/nacos/logs:/home/nacos/logs \
  -e JVM_XMS=256m -e JVM_XMX=512m -e JVM_XMN=128m \
  --memory=768m \
  nacos/nacos-server:v3.2.3
```

控制台：`http://<服务器IP>:8880/nacos`。首次登录后修改默认账号口令。

> **启动失败的常见原因（务必先看）**：Nacos 3.x 用 JWT 签名，`NACOS_AUTH_TOKEN` 必须
> **Base64 编码且解码后 ≥ 32 字节**，否则容器反复重启并报
> `the length of secret key must great than or equal 32 bytes`。
>
> ```bash
> # 生成一份合格的 token（解码 32 字节）
> openssl rand -base64 32
> # 校验
> echo -n '<token>' | base64 -d | wc -c     # 必须 ≥ 32
> ```
>
> 三项都必填：`NACOS_AUTH_TOKEN`、`NACOS_AUTH_IDENTITY_KEY`、`NACOS_AUTH_IDENTITY_VALUE`；
> 任一为空镜像会直接 `exit 255`。修改后需 `docker compose up -d --force-recreate nacos`
> （`docker restart` 不会重读 `.env`）。

> 端口映射为宿主 `8300/9300/8880`，容器内仍是 `8848/9848/8080`。
> **与 Elasticsearch 的冲突处理**：Nacos 客户端默认用「server-addr 端口 + 1000」连接 gRPC，
> 8300 + 1000 = 9300，恰好是 ES 的传输端口，所以 **ES 的传输端口在宿主机改映射为 `9301`**（容器内不变），
> 后端连接 ES 用的是 HTTP REST `9200`，**不需要任何 JVM 参数**。
> 如果服务器上 8848/9848 可用，也可以改回 `-p 8848:8848 -p 9848:9848 -p 8080:8080`。

## 三·补、Nacos 与后端分属两台服务器

后端通过 HTTP 和 gRPC 两个通道访问 Nacos，两台机器部署时注意三点：

| 项 | 写法 |
| --- | --- |
| 地址 | 填 **Nacos 那台机器的 IP**（内网互通优先用内网 IP，跨机房用公网 IP），端口用宿主 HTTP 端口 `8300` |
| 端口 | Nacos 主机需放通 **8300（HTTP）和 9300（gRPC = 8300 + 1000）**；只开 8300 时后端能读到配置但长连接会失败 |
| 命名空间 | 填**命名空间 ID**（控制台「命名空间」页 ID 列，3.x 为 UUID），不是名称；用 public 则删掉该行 |

`bootstrap.properties` 最小示例（Nacos 在 `10.0.0.5`）：

```properties
spring.application.name=nacos
spring.profiles.active=cloud
spring.config.import=optional:nacos:application-cloud.yml?group=DEFAULT_GROUP&refreshEnabled=true

# 命名空间 ID（public 命名空间请删除本行）
spring.cloud.nacos.config.namespace=0f2b1c3d-4e5f-6789-abcd-ef0123456789

# Nacos 服务器 IP + 宿主 HTTP 端口；gRPC 端口由客户端按 +1000 推导为 9300
spring.cloud.nacos.config.server-addr=10.0.0.5:8300

spring.cloud.nacos.config.file-extension=yml
spring.cloud.nacos.config.prefix=application
spring.cloud.nacos.config.username=${NACOS_USERNAME:nacos}
spring.cloud.nacos.config.password=${NACOS_PASSWORD:}
spring.cloud.nacos.config.refresh-enabled=true
```

> 本项目**未引入 `nacos-discovery` 依赖**，`@EnableDiscoveryClient` 没有实现类，属于空操作；
> `spring.cloud.nacos.discovery.*` 写不写都不影响启动，建议直接删除，少一个填错的地方。
>
> 配置必须建在**同一个命名空间**下（dataId `application-cloud.yml`、group `DEFAULT_GROUP`），
> 否则后端会连上 Nacos 却找不到配置，报数据源缺失。

## 四、Nacos 配置

1. 登录 Nacos 控制台，新建配置：dataId `application-cloud.yml`、group `DEFAULT_GROUP`、格式 YAML。
2. 内容参照 [`nacos-template.yml`](nacos-template.yml)，把地址、口令、JWT 密钥、AI Key 换成生产值。
3. 建议把 `knife4j.production` 设为 `true`，关闭生产环境的接口文档。
4. 把 [`bootstrap.properties.template`](bootstrap.properties.template) 复制为
   `aurora-xinchen/src/main/resources/bootstrap.properties`，填入命名空间 ID 与 Nacos 地址。

## 五、部署后端

### 1. 打包

```bash
cd aurora-xinchen
mvn -B -ntp clean package -DskipTests
# 产物：target/aurora-xinchen-0.0.1.jar
```

### 2. 上传并启动

仓库自带的后端镜像定义见 [`aurora-xinchen/Dockerfile`](../aurora-xinchen/Dockerfile)
（基于 `eclipse-temurin:25-jre`）。把 jar 与 Dockerfile 上传到同一目录后：

```bash
mkdir -p /usr/local/aurora-xinchen
# 上传 target/aurora-xinchen-0.0.1.jar 与 aurora-xinchen/Dockerfile 到该目录
cd /usr/local/aurora-xinchen
docker build -t aurora-xinchen:latest .
docker run -d --name aurora-xinchen --restart=always \
  -p 8080:8080 \
  -e NACOS_PASSWORD='<Nacos 口令>' \
  aurora-xinchen:latest
```

`NACOS_PASSWORD` 必须注入，否则 Nacos 拒绝连接。也可以改为在宿主机 `/etc/environment`
或 systemd 服务中设置环境变量。

> 端口口径：Nacos gRPC 用 `8300 + 1000 = 9300`（默认，无需任何 JVM 参数）；
> ES 传输端口在宿主机改映射为 `9301`，后端只连 ES 的 HTTP `9200`。两部分互不影响。

### 3. 更新脚本（可选）

`aurora-start.sh` 便于一键重建容器：

```bash
SOURCE_PATH=/usr/local/aurora-xinchen
SERVER_NAME=aurora-xinchen
IMAGE_NAME=aurora-xinchen:latest

CID=$(docker ps -aq -f "name=^${SERVER_NAME}$")
if [ -n "$CID" ]; then docker stop "$CID" && docker rm "$CID"; fi
cd "$SOURCE_PATH"
docker build -t "$IMAGE_NAME" .
docker run -d --name "$SERVER_NAME" --restart=always -p 8080:8080 \
  -e NACOS_PASSWORD='<Nacos 口令>' "$IMAGE_NAME"
```

> shell 脚本需保存为 Unix 换行（LF）。Windows 编辑器可用 Notepad++「编辑 → 文档格式转换 → 转为 Unix」。

验证：`curl http://127.0.0.1:8080/`，返回 JSON 且 `flag=true` 即启动成功。

## 六、部署前端

### 0. 部署前需要替换的外域资源

前台 `aurora-blog/public/index.html` 仍引用作者自有域名的资源，部署到自己的域名/仓库前**必须替换或删除**：

| 资源 | 位置 | 处理建议 |
| --- | --- | --- |
| `waifu.css`（Live2D 样式） | `public/index.html` 的 `<link>` | 改为本地 `vendor/` 或删除（Live2D 组件自身的样式来自 `src/assets/waifu.css`） |
| `cursor.css`、`star.js`（光标与星空特效） | `public/index.html` | 改为本地文件或删除 |
| QQ 互联 `qc_jssdk.js`、`data-appid`、`data-redirecturi` | `public/index.html` 与 `src/config/config.ts` | 换成自己的 AppID 与回调域名 |
| `README.md` 中的效果站链接 | `README.md` | 改为自己的站点或删除 |

`jquery` 与 `KaTeX` 已本地化到 `public/vendor/`（队列项 021），无需外部依赖。

### 1. 修改前端配置

`aurora-blog/src/config/config.ts`：

```ts
qqLogin: {
  QQ_APP_ID: '你自己的 APP_ID',
  QQ_REDIRECT_URI: 'https://你的前台域名/oauth/login/qq'
}
```

`aurora-blog/public/index.html` 中的 QQ SDK：

```html
<script
  src="http://connect.qq.com/qc_jssdk.js"
  data-appid="你自己的 APP_ID"
  data-redirecturi="https://你的前台域名/oauth/login/qq"></script>
```

如果站点不使用 HTTPS，注释掉两个 `index.html` 中的：

```html
<meta http-equiv="Content-Security-Policy" content="upgrade-insecure-requests" />
```

### 2. 构建

```bash
cd aurora-blog  && npm ci && npm run build    # 产物 aurora-blog/dist
cd aurora-admin && npm ci && npm run build    # 产物 aurora-admin/dist
```

要求 Node.js 24。前台包含 TypeScript 类型检查（`strict`），构建失败请先修类型错误。

### 3. 方式一：源码部署 + nginx 反向代理

把 `aurora-blog/dist` 重命名为 `blog`、`aurora-admin/dist` 重命名为 `admin`，上传到
`/usr/local/aurora-vue/` 下（即 `/usr/local/aurora-vue/blog`、`/usr/local/aurora-vue/admin`）。

`/usr/local/nginx/nginx.conf`（HTTP 版；HTTPS 版再加 443 server 块与证书配置）：

```nginx
events {
    worker_connections 1024;
}

http {
    include       mime.types;
    default_type  application/octet-stream;
    sendfile      on;
    keepalive_timeout 65;

    client_max_body_size    100m;
    client_body_buffer_size 10m;

    gzip on;
    gzip_min_length 1k;
    gzip_comp_level 4;
    gzip_types text/plain application/javascript application/x-javascript text/css
               application/xml text/javascript image/jpeg image/gif image/png image/svg+xml;
    gzip_vary on;

    server {
        listen       80;
        server_name  前台域名;

        location / {
            root  /usr/local/aurora-vue/blog;
            index index.html;
            try_files $uri $uri/ /index.html;
        }

        location ^~ /api/ {
            proxy_pass http://<后端IP>:8080/;
            proxy_set_header Host              $host;
            proxy_set_header X-Real-IP         $remote_addr;
            proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        }
    }

    server {
        listen       80;
        server_name  后台域名;

        location / {
            root  /usr/local/aurora-vue/admin;
            index index.html;
            try_files $uri $uri/ /index.html;
        }

        location ^~ /api/ {
            proxy_pass http://<后端IP>:8080/;
            proxy_set_header Host              $host;
            proxy_set_header X-Real-IP         $remote_addr;
            proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        }
    }
}
```

```bash
docker run -d --name nginx --restart=always -p 80:80 \
  -v /usr/local/nginx/nginx.conf:/etc/nginx/nginx.conf \
  -v /usr/local/aurora-vue:/usr/local/aurora-vue \
  nginx
```

### 4. 方式二：使用仓库前端镜像

仓库提供 [`Dockerfile.frontend`](../Dockerfile.frontend) 与 [`nginx.frontend.conf`](../nginx.frontend.conf)，
多阶段构建后由 nginx 统一提供：blog 在 `/`，admin 在 `/admin`。

```bash
# 在仓库根目录执行
docker build -f Dockerfile.frontend -t aurora-vue:latest .
docker run -d --name aurora-vue --restart=always -p 8081:80 aurora-vue:latest
```

该容器只负责静态文件与 history fallback，**不包含 `/api` 反向代理**。生产环境通常在外层再放一个
nginx / 负载均衡，把 `/api/` 代理到后端 `8080`，同时把前台域名转发到本容器 `/`、后台子路径转发到 `/admin/`。

## 七、CI（GitHub Actions）

[`.github/workflows/aurora.yml`](../.github/workflows/aurora.yml) 在 **push 到 `main`** 时：

1. 用 JDK 25 打包后端，构建并推送 `<DOCKER_USERNAME>/aurora-xinchen:latest`；
2. 用 Node 24 构建前台与后台，构建并推送 `<DOCKER_USERNAME>/aurora-vue:latest`；
3. 通过 SSH 登录部署主机，执行服务器上的更新脚本重启容器。

需要在仓库 **Settings → Secrets and variables → Actions** 中配置：

| Secret | 用途 |
| --- | --- |
| `DOCKER_USERNAME` / `DOCKER_PASSWORD` | Docker Hub 推送账号 |
| `REMOTE_HOST_A_IP` / `REMOTE_HOST_A_PASSWORD` | 前端主机 |
| `REMOTE_HOST_B_IP` / `REMOTE_HOST_B_PASSWORD` | 后端主机 |

部署主机上需预先放好 `aurora-xinchen.sh` / `aurora-vue.sh` 更新脚本。

## 八、常见问题

| 现象 | 处理 |
| --- | --- |
| 后端启动失败，日志提示连接 MySQL/Redis 失败 | 检查中间件容器与安全组/防火墙端口 |
| 后端提示 Nacos 认证失败 | 确认已注入 `NACOS_PASSWORD`，且 Nacos 账号口令与配置一致 |
| 前台接口 404 或跨域 | 检查 nginx 的 `/api/` 代理是否指向后端 `8080`，并保留 `try_files` fallback |
| 后台上传图片失败 | 检查 MinIO/OSS 配置与 bucket 是否已创建、读写权限是否开放 |
| 搜索无结果 | 确认 `search.mode`、ES 是否启动、IK 分词器版本是否与 ES 一致 |
| 修改网站信息 | 登录后台 →「系统管理 → 网站管理」 |
